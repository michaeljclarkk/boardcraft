# Architecture and owner map

| Boundary | Owner | Responsibility |
|---|---|---|
| Account sessions | [`sign_in`, `resolve`, `revoke`](../crates/account/src/lib.rs) and [schema](../crates/account/migrations/0001_account_session.sql) | Verify an existing active account under a row lock. Commit a digest linked to its UUID before returning a bearer. Resolve the current role from that link; logout deletes only that digest. |
| Nonvisual sign-in | [`PasswordStep` and `SessionClient`](../crates/account/src/client.rs) | Advance locally, submit credentials, then resolve before exposing a ready account. Reopen takes only a token; an unavailable store leaves it in memory for retry. The desktop development actor remains a separate recovery setting. |
| Browser board preview | [Page and history](../crates/mobile-edit-host/src/preview/page.js) → [exact-origin binding](../crates/mobile-edit-host/src/preview/binding.js) → [preview session table](../crates/mobile-edit-host/src/browser_session.rs) → [account and navigation handlers](../crates/mobile-edit-host/src/lib.rs) | The address identifies the destination. The host owns the bearer; a matched HttpOnly cookie and origin-local binding select it. Tabs resolve before mounting a destination and discard stale visits on a credential-free change notification. Each board operation checks current access in its own transaction. Native clients continue to present explicit bearers. |
| Browser root selection | [Mounted checkboxes, anchor and toolbar](../crates/mobile-edit-host/src/preview/selection.js) → [selected board read](../crates/mobile-edit-host/src/preview/page.js) | Checks belong to the board visit. The first group or anchored range gesture resolves ordered IDs from the bounded grouped GET; replacing the table snapshot invalidates that cache. Adding a group or range puts that entire ordered block last. Checking boxes has no database writes. |
| Archive and restore a root | [Dialog and recovery list](../crates/mobile-edit-host/src/preview/lifecycle.js) → [selected-board authorization](../crates/mobile-edit-host/src/access.rs) → [`archive_page` / `transition_root`](../crates/board/src/store/lifecycle.rs) | The inventory owns the restore baselines. The store locks the board, checks the original item and advances both revisions with a command-bound receipt. The host holds current Owner access through commit, including on replay. |
| Create a group | [Add group dialog](../crates/mobile-edit-host/src/preview/group-create.js) → [selected Owner authorization](../crates/mobile-edit-host/src/access.rs) → [`create_group`](../crates/board/src/store/group_fields.rs) | The dialog owns the proposed ID, raw name, colour and board baseline. Under the board lock the store acknowledges an existing local ID without updating it. For a new ID it checks the revision, uses the active-group count as position and commits the insert with the board revision. |
| Reorder physical groups | [Heading drag](../crates/mobile-edit-host/src/preview/heading-drag.js) and [heading menu](../crates/mobile-edit-host/src/preview/group-lifecycle.js) → shared submission → selected Owner POST → [`reorder_groups`](../crates/board/src/store/group_order.rs) | The menu swaps neighbours; the pointer inserts the moving ID at a physical heading edge. Both use the accepted snapshot. The store locks the board and checks its revision and complete active membership. Dense ranks and every included revision commit together. Recovery reads without replay. |
| Edit a group | [Heading](../crates/mobile-edit-host/src/preview/names.js) and [menu](../crates/mobile-edit-host/src/preview/group-lifecycle.js) → [group dialog](../crates/mobile-edit-host/src/preview/group-create.js) → selected Owner PUT → [`edit_group`](../crates/board/src/store/group_fields.rs) | An existing board-local ID identifies the active record. Both revisions guard the write, including an unchanged Save. Review reads both accepted fields; adoption changes the draft baselines without writing. |
| Archive and restore a group | [Group menu and Undo](../crates/mobile-edit-host/src/preview/group-lifecycle.js) and [recovery list](../crates/mobile-edit-host/src/preview/lifecycle.js) → [`transition_group` / `archived_groups`](../crates/board/src/store/group_lifecycle.rs) | A board revision guards the transition of one board-local group. Its state and the two revisions commit together under current Owner access. Child state and order remain independent. The recovery read pins the revision across item and group inventories; group continuation rechecks it. |
| Move a toolbar selection | [Dialog and review](../crates/mobile-edit-host/src/preview/selection-move.js) → [selected-board POST](../crates/mobile-edit-host/src/lib.rs) → [`move_selected_items`](../crates/board/src/store/selection_move.rs) | The dialog owns an ordered list of IDs, revision baselines and one operation ID. Under current write access the store serializes the move with other order commands, appends to the physical group and commits both field stamps and the [receipt](../crates/board/migrations/0007_selection_move.sql). Replay returns stored affected IDs; only the grouped read supplies display order. |
| Connected Android sign-in | [Kit login](../android/src/login.rs) → [`EditClient`](../crates/mobile-edit-client/src/lib.rs) → [loopback session handler](../crates/mobile-edit-host/src/lib.rs) | The Kit view owns the two input steps. The host delegates credential verification and bearer resolution to the account operations. Only a resolved client loads the board; the activity keeps its client in memory for reads and saves. |
| Selected browser name | [Mounted editor and recovery actions](../crates/mobile-edit-host/src/preview/names.js) → [preview PUT](../crates/mobile-edit-host/src/lib.rs) → [`authorize`](../crates/mobile-edit-host/src/access.rs) and [`rename_item_at_revision`](../crates/board/src/store.rs) | The current board visit owns entry revisions, pending labels and failed requests by item ID. The host locks the current role and catalog grants through the rename transaction. Only its committed row updates the accepted spelling. |
| Connected Windows sign-in | [Connected window](../crates/desktop/src/connected.rs) → [`EditClient`](../crates/mobile-edit-client/src/lib.rs) → [protected board handler](../crates/mobile-edit-host/src/lib.rs) | `configured_session` checks the process-supplied session against the selected loopback origin at launch. It and interactive sign-in converge on `Connected::load`: background work resolves the session and reads the authorized rows in host order. The session lives in the window; direct-store edits and local actor recovery belong to the separate developer entry. |
| Connected Windows name edit | [Kit row](../crates/desktop/src/main.rs) → [`Connected::save`](../crates/desktop/src/connected.rs) → `EditClient::rename` | The row captures the entry spelling and revision. The window sends a changed draft once. The [host access decision](../crates/mobile-edit-host/src/access.rs) supplies the read-time edit hint and enforces current permissions inside the save transaction. Only the committed row changes the accepted name. |
| Android cold session restore | [`session::open`](../android/src/session.rs) → [Keystore record](../android/java/SessionStore.java) and `EditClient::resolve` | Save the issued bearer for the exact loopback origin before resolving it. Read only that origin on reopen. The store authenticates both origin and version; only the host can authorize a board. Rejection and acknowledged logout remove that record; transport failure retains it. |
| Connected logout | [Windows board action](../crates/desktop/src/connected.rs) and [Android board action](../android/src/lib.rs) → [`EditClient::logout`](../crates/mobile-edit-client/src/lib.rs) → [session POST](../crates/mobile-edit-host/src/lib.rs) → [`revoke`](../crates/account/src/lib.rs) | The host revokes the presented bearer independently of board access. Each view waits for acknowledgment before dropping its client and rows; a connection failure leaves the board available for explicit retry. Windows returns to a new identifier field without reading the launch environment again. |
| Board items | [`Board::rename_item` and `interactive_title`](../crates/board/src/lib.rs) | Own non-nil UUID identities, item order and the shared interactive title rule. |
| Durable boards | [`store`](../crates/board/src/store.rs) and [schema](../crates/board/migrations/0001_boards.sql) | Migrate the schema, round-trip ordered boards, and return a board-scoped rename result after commit. |
| Physical board groups | [Membership migration](../crates/board/migrations/0003_board_groups.sql) → [`load_groups` / `load_items` / `save_title`](../crates/board/src/store.rs) | The composite foreign key binds each item to a group on its own board. Selected browser reads include active empty groups; native reads flatten the active groups in order. Rename locks the item for update and its active group for share through commit. |
| Item revisions | [Revision migration](../crates/board/migrations/0002_item_revision.sql) and [store operations](../crates/board/src/store.rs) | Start at 1. Rename advances the changed item's revision; changing its group also stamps the group field. A relative reorder stamps both group and position on the selected item, even though its group stays the same. |
| Reorder one root in a group | [Pointer grip](../crates/mobile-edit-host/src/preview/reorder.js) → [matched preview POST](../crates/mobile-edit-host/src/lib.rs) → [`reorder_group_item`](../crates/board/src/store/reorder.rs) | The grouped GET supplies the board revision from the same snapshot. The store locks the board against other reorders, appends and group moves; it checks the selected revision and anchor, ranks the entire bounded group, and advances the board and selected item with the [receipt](../crates/board/migrations/0006_group_reorder.sql) in one transaction. Only an identical command under current write access can replay its acknowledgment. |
| Selected group item move | [Row menu, dialog and failed-move review](../crates/mobile-edit-host/src/preview/moves.js) → [preview PUT](../crates/mobile-edit-host/src/lib.rs) → [`move_group_item`](../crates/board/src/store.rs) | Current selected-write access, the item and both active groups stay locked through commit. The [v5 migration](../crates/board/migrations/0005_item_group_move.sql) allows ties without renumbering. At equal positions undated v4 rows sort first, then dated rows by creation time, with UUID as the final key. Original creation group and spelling identify a create replay even after a move. |
| Selected group item creation | [Group form](../crates/mobile-edit-host/src/preview/names.js) → [preview POST](../crates/mobile-edit-host/src/lib.rs) → [`store::create_group_item`](../crates/board/src/store.rs) | The form owns the proposed UUID and raw spelling. The selected-write transaction locks the active group before allocating its next position. [Creation provenance](../crates/board/migrations/0004_item_creation.sql) distinguishes explicit creator replays from ID collisions and leaves snapshot rows unattributed. |
| Mobile board read and name save | [EditClient](../crates/mobile-edit-client/src/lib.rs) → [loopback handler](../crates/mobile-edit-host/src/lib.rs) → `store::load_items` / `store::rename_item_at_revision` | Serve one synthetic board. The client sends its in-memory bearer in the Authorization header. Only the host talks to PostgreSQL. |
| Loopback board access and discovery | Account `resolve_on` → [`authorize` and `list_visible_boards`](../crates/mobile-edit-host/src/access.rs); [policy migration](../crates/mobile-edit-host/migrations/0002_navigation.sql) | Both operations apply the same active workspace and board rules. Discovery limits visible workspaces first, then visible boards globally. The selected-board GET checks the current catalog policy and holds the session, role, policy and supporting grant locks through the ordered read. Direct GET/PUT remain target-scoped. Viewers cannot rename. Legacy private grants without catalog metadata retain direct access only. |
| Windows board selection and sharing | [Kit navigation controls](../crates/desktop/src/connected/navigation.rs) → `EditClient::list_boards` / `read_selected_board`; [Board address](../crates/desktop/src/connected/board_link.rs) | The accepted page retains its UUID. Both pasted and new-window links reduce to a canonical same-origin ID before the opening window reads it with its own client. Only returned items reach the read-only view. Back and Refresh request current visibility. |
| Android board selection | [Browse intent](../android/src/connection.rs) → existing Android account restore/sign-in → [Kit picker and Back](../android/src/navigation.rs) | The picker uses the same list and selected-read HTTP operations as Windows. Selection is read-only and lasts only in the view. System Back and the visible return control both request current visibility. |
| Desktop board editor | [Kit window and rows](../crates/desktop/src/main.rs), [`InlineEdit` and `Save`](../crates/desktop/src/lib.rs) | The Kit input owns the unsubmitted draft. Each row's `InlineEdit` keeps its accepted name and any pending or rejected request. `Workbench` runs the conditional save off-thread and presents failure actions for that row's name. Explicit retry reads the current title before the locked conditional write. |
| Windows failed-name recovery | [`Recovery`](../crates/desktop/src/recovery.rs) and [`Workbench`](../crates/desktop/src/main.rs) | After loading the board, attach failures by item UUID within the explicit local actor/board scope. Submission removes the matching failure before the database operation; only rejection records a raw request and reason. A locked check of the failure token prevents stale cleanup from deleting a later failure. PostgreSQL remains authoritative for the accepted board. |
| Windows name drafts | [Kit row](../crates/desktop/src/main.rs), [scoped draft record](../crates/desktop/src/recovery.rs), [`finish_name_edit`](../crates/board/src/store.rs) | A change to the input records its exact text and entry spelling/revision separately from submitted failures. On reopen, the entry spelling decides whether to submit. The transaction checks both the entry revision and the title last observed from PostgreSQL. |
| Android fixture board editor | [`BoardView`](../android/src/lib.rs), [launch arguments](../android/src/connection.rs), [APK build](../android/build-debug.ps1) | One Kit Root owns the board view and input. Without arguments it opens the offline fixture. UUID and port select a connected host but supply no session: the protected host rejects the read until a native session is available. |
| Framework versions | [Desktop package](../crates/desktop/Cargo.toml) and [lockfile](../Cargo.lock) | Select the Kit release as a unit; use its GPUI re-exports rather than adding an independent GPUI revision. |
| Development database | [Local helper](../scripts/postgres.ps1) | Own the disposable local cluster and test login. |
| Milestone execution | [Runner](../scripts/run.mjs) | Dispatch one worker per packet, check its handoff, run gates and record a checkpoint. |

For board edits, the intended path is Kit editor → named Rust operation → PostgreSQL transaction → accepted value back to the editor. The draft remains view state. Add owner links as each boundary lands; avoid creating empty crates to match this diagram.

## Custom GPUI controls

When Kit cannot reproduce a required interaction, put the reusable control in `crates/boardcraft-ui` as a library and list it here. Its public API accepts display values, state and events; it must not depend on the desktop binary, domain entities, database, routing or services. The desktop caller maps control events to boardcraft operations. Include a minimal runnable example using synthetic values, document keyboard/focus behavior and test the interaction that justified the control. A consumer should be able to use the control as a path dependency in another GPUI app. Create the crate with the first real control.
