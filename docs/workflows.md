# Workflow and gap register

The full product is in scope. The rows below start the first packet; they are not an exhaustive inventory. Before queuing each remaining area, map its screens, native and API consumers, persisted formats, permissions, background effects and failures to synthetic acceptance cases. Cover workspaces, boards and groups, column types, views and forms, relationships, imports/exports, search, conversations/files, workspace chats, activity, personal work, teams/accounts, settings, assistant workflows, notifications, integrations, automations and mobile flows. Reconcile this inventory against the approved reference; an unlisted workflow remains in scope. Record private evidence pointers separately from public acceptance criteria.

Use one row per observable user action. A planned test name is not evidence. When an implementation lands, link the rule owner, the automated check and the runtime observation in the packet handoff.

The 05–09 Android observations below predate protected HTTP. [Packet 15](../handoffs/15-android-kit-sign-in.json) repeated the device probe cases with an authorized Member and the connected Kit journey with interactive sign-in. The same activity resumed the unsaved `Amber` draft after HOME; Windows showed the saved `Coral` on that board. The offline frame still opens without sign-in or HTTP.

Packet 13 comparison: the reference login component ran against its account operations in a disposable database with an in-memory request adapter. Unknown, whitespace-only and oversized nonempty identifiers all advanced without a request; only password submission rejected them. Correction resolved the Viewer. An unavailable resume retained the token, retry observed the new role under the same ID, and logout left the other session usable. This compares state transitions, not network transport, native UI or credential-format compatibility. Lookup tests cover mixed-case ASCII, not full Unicode normalization. The fixture models Viewer and Member; other roles, account management and enforcement on existing write paths remain open.

The persistence fixture covers board scope and interactive titles (trim, reject blank, at most 255 UTF-16 code units). Snapshot creation and loading preserve existing spelling; historical import behavior remains open. A name-only service edit accepts a known positive item revision and rejects a future one. Revision rules for other fields, active groups, write permissions and field editability remain open.

The Windows comparison covers name-cell entry and completion. It does not establish full browser/server failure handling or concurrency parity: Windows still checks the expected title in its conditional transaction. Android HOME/resume retained a live draft; same-process configuration changes, navigation Back/discard, live conflict revalidation and durable draft restoration remain open.
