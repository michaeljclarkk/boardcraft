# 07-android-kit-edit

Load a disposable two-row board in the Android Kit window using the existing `EditClient` and production `Host`. Replace the second title in the actual focused Kit Input, submit a blank draft, keep the editor open on validation failure, correct and save. Keep network work off the frame thread. Bind the draft to the loaded ID and revision, prevent duplicate submissions and use the committed result. Never compile credentials into the APK. Preserve the 06 offline fixture when launched without connection arguments.

Gate: `node scripts/android-kit-edit.mjs`. Build the 06 debug package and a host-side Cargo example `kit_edit_fixture` in `boardcraft-mobile-edit-host`. The example reuses the existing test fixture/schema, starts the production host for ordered titles `Review sketch` / `Ink`, and prints one JSON line `{ "board": "<uuid>", "port": <port> }`. On stdin `original` or `saved`, reconnect to that same `rustday_test` schema and assert **both** IDs, order, titles and revisions (`1,1` or `1,2` with second title `Coral`), then print `ok`; exit/clean up on EOF. Never pass a database URL to Android. The gate owns package install and an exclusive `adb reverse --no-rebind` mapping. It launches the fixture activity with `--es board <uuid> --ei port <device-port>`.

- Actual foreground frames: `Sample board` / `Review sketch` / `Ink`. Tap `Ink`, then focus the Kit Input under `Editing name`. Use the Android keyboard path, including deletion. The initial 06 NativeActivity displayed the input but did **not** show the IME or change `Review artwork` when text was sent. Supply the platform input connection for the pinned native host. An invisible IME adapter is fine; the visible editor, draft, controls and all business decisions belong in Rust. No custom test commands, Java form, canned replies or duplicate text overlays.
- Clear the name. Save → `Name required`; keep the empty input available, sibling unchanged. Require a fresh `original` readback **before correction**. Enter `Coral` in the same editor and observe it in the real input. With IME visible, system Back must hide it, leave the same draft visible and not save. Tap `Save`; observe the committed title in display mode and require `saved` readback. Each stage must fail closed on stale/missing screens or unexpected store results. Screenshots and private source notes stay untracked.
- Preserve 05 and 06. Run both formatting checks, runner regressions and portable workspace tests. Re-run the 06 gate against the new APK. Full navigation Back (including discard/keep editing), lifecycle/recreation, conflict/transport recovery and same-board Windows window comparison remain open; IME dismissal alone does not prove them. Record actual operator results before runner verification if worker device/packaging commands are restricted.
