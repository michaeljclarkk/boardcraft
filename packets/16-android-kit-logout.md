# 16-android-kit-logout

On a connected Android board, offer a Kit `Log out` action. The reference mobile command waits for the logout POST: a connection failure reports an error and leaves the current session and protected view in place. On success the server has deleted only the presented session digest; the client clears its local session and reloads at the identifier step. Translate this through `EditClient` and a production loopback POST using the existing bearer and account `revoke`. No account-wide deletion, board grant requirement, automatic retry, or fixture auth route. Repeating a revoke for an already-removed well-formed bearer is harmless. Do I/O off the UI thread, guard duplicate actions, and prevent late completions from repopulating the signed-out view.

- Host gate: require enabled `loopback_board_access::explicit_logout_isolates_sessions` over real HTTP. Sign in twice as the same synthetic Member; both clients can read. Log out A; on new connections check only B's verifier remains linked to that UUID, and both ordered board rows/revisions are unchanged. A's old bearer fails resolve, read and rename; B still resolves and reads. Never include secrets or digests in assertion output.
- Device gate: `node scripts/android-kit-logout.mjs`, extending the existing `gate(afterSave)` journey on its disposable fixture. After 15/07 save (`Review sketch`/1, `Coral`/2, IDs 42 then 17), fixture command `peer` signs in a second client for the same Member in memory, retains it and checks both sessions. Remove only this test's adb reverse before tapping `Log out`; require a retryable failure with the board still visible. `logout-failed` checks both original sessions and both accepted rows via fresh connections. Restore the reverse using `--no-rebind`. Without signing in again, edit row 17 to `Jade` in the Kit Input and save; `still-signed-in` checks `Jade`/3 and both sessions. Open a new unsaved draft `Amber`, dismiss the IME, then tap `Log out`. Require `Username or email` and `Next` in the foreground with all board, editor, draft, save and logout controls absent. `logged-out` checks only the peer's verifier remains, its client resolves and reads, and IDs/order/revisions are unchanged. Sign in again in the same activity: require clean `Review sketch`/`Jade` display with no draft. No fixture-issued Android bearer or direct state injection. Use the inherited stdin-only credential entry and private AVD preflight.
- Runner: preserve all packet 15 gates (including both 05 cases, offline 06, connected 07–08, Windows readback and cold sign-in); additionally enforce the named host case and logout journey. Coordinator owns drivers and runner; worker owns implementation, Rust fixture, affected docs and handoff. Record device/DB and reference runtime results separately from source tracing. No verification marker without passing gates.

Driver invocation: use the tracked `scripts/android-kit-edit.mjs --logout` for the logout journey rather than a new driver file. On a pre-delivery failure display `Could not log out` while keeping `Log out` available for retry.
