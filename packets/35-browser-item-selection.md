# 35-browser-item-selection

Select roots in the selected board's expanded, unsorted physical groups. Both Member and Viewer can select. Give each row a native checkbox named `Select <item name>`, each group a checkbox named `Select all items in <group name>`. Bind by board, group and item ID even when the accessible names match. A checked row is visibly marked. The group checkbox is unchecked for none, **indeterminate** for some and checked for all; an empty group's checkbox is disabled and unchecked. Selecting a mixed group adds its remaining rows once; unchecking a full group removes only its rows. There is no board-wide checkbox in this layout. While nonempty, show the count (`N selected`) in `Selected item actions` with an accessible `Clear item selection` button. Clearing removes all checks, row marks and the toolbar.

An ordinary row toggle sets the range anchor, including when unchecking. Shift-click without an anchor acts like an ordinary toggle. Otherwise, take the inclusive interval between the anchor and the target in **displayed group and row order**, in either direction. A newly checked target adds the interval; an unchecked target removes it. Keep selections outside the interval. Shift, group toggles and toolbar Clear do **not** replace the anchor on the same mounted table. Reload starts with no selection or anchor. These are selection gestures, not row opening, renaming, reordering or moving.

**Compared fixture.** Reuse [34's seven-row fixture](34-browser-group-item-reorder.md) without reordering it: `g-90 Work [73 Sketch, 61 Ink, 67 Ink, 77 Fold]`, `g-10 Reserve []`, `g-20 Work [59 Ink]`. Neither the archived group's row nor board 202's row is selectable. The mounted reference grid and toolbar ran against scoped group-summary reads in a disposable database, with actual Chromium inputs. The following sequences are in display order:

| Gesture | Checked IDs | What distinguishes the result |
|---|---|---|
| Check 67; Space twice on its focused checkbox | `[67] → [] → [67]` | 61 stays unchecked; mixed first Work; toolbar disappears at zero. |
| Check 59; click the mixed first Work header | `[67,59] → [73,61,67,77,59]` | Both Work headers checked, `5 selected`; no duplicate 67. |
| Uncheck first Work; try empty Reserve; Clear | `[59] → [59] → []` | Other Work survives the group removal; Clear hides the toolbar. |
| Shift-click 67, then Shift-click 77 | `[67,77,59] → [67]` | Still anchored at 59 after group toggles and Clear; reverse inclusive range crosses empty Reserve. |
| Reload; Shift-click 73; plain click 67 | `[] → [73] → [73,67]` | No previous anchor; 73 lies outside the next interval. |
| Shift-click 59 with the range read unavailable; retry deliberately, then Shift-click 59 again | `[73,67] → [73,67,77,59] → [73]` | Error leaves the entire prior selection intact. Retry adds the forward range; repeated Shift removes it without removing 73. Works as Viewer. |

**Read boundary.** Ordinary row toggles and Clear are local. The reference resolves uncached groups/ranges by ordered, authorized reads, then caches group summaries for that table generation. For Boardcraft's complete, bounded physical grid, reuse the [existing grouped GET](../crates/mobile-edit-host/src/preview/page.js) once per gesture that needs uncached groups; no new route, schema, operation receipt or stored selection. Resolve the whole interval before changing the selection. Repeated use of resolved groups needs no request. Invalidate cached summaries on a new board snapshot; if an endpoint of the range is no longer available, fail without a partial selection and offer a fresh read. Ignore late results after leaving the board. Keep the existing unauthorized/unavailable destination and session handling. Do not infer a paged group's membership from mounted DOM nodes or widen the preview read limit.
