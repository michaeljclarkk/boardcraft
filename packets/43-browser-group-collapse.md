# 43-browser-group-collapse

Fold and reopen physical groups on the selected board's **main table**. A collapsed group still exists, in the same place, with its full item count. The heading has a separate **Toggle ‹name›** button (`aria-expanded`) and a menu. The menu offers **Collapse group** and **Collapse all groups** on an expanded heading; both verbs become **Expand** on a collapsed heading, even in a mixed table. Empty groups have the same controls. Keep the heading, count, menu and name gestures available. Hide the group's table body, including its header checkbox, row grips, names, checkboxes and add-item entry, from pointer and keyboard interaction. Restore them in accepted order on expand. Folding does not run an item action, select a row or start a drag.

**Who owns the fold?** With no personal view selected, the reference resolves a plain board address to its preset main table. On that view, an Owner **or Member** saves presentation; another authorized reader sees the same folded IDs. A Viewer can override the shared setting in either direction for this mounted table, including **all**, without a mutation. Document reload discards those overrides and selection, then reads current access and shared presentation. A fresh visit must not inherit local state from an earlier board, tab or session. Don't implement this by hiding rows in the board read or storing a per-user browser preference.

There is a distinct reference component fallback when mounted *without* presentation or its callbacks: an Owner's first single toggle writes the physical group; all-groups changes are local, and a subsequent single toggle of a locally overridden ID stays local. Non-Owners toggle locally there. That is **not** the normal routed main-table save. Implement the routed case here; no second group mutation, general view editor, personal view choice, derived grouping, subitem or native scope in this packet.

**Compared fixture.** At board revision 7, main-table revision 1 and no folds, A and B are both `Work` (tied at position 3, A first by ID), C is empty `Reserve` at 12. A has `Ink` 59; B has `Ink` 61 and 63. Hidden group/root 57, individually archived 67 and the other board's 62 are never displayed. The reference also has child 64 under 61; leave subitem storage out of the preview. A fold save advances **only** the main-table revision and its board revision, once each, even for all groups. IDs belong to the view on that board, not to heading labels or list indices. Membership is a set; saving all from mixed state retains existing IDs and adds the missing displayed IDs. Expand all removes the displayed IDs. Neither operation reorders the grid.

| Reference gesture | Visible result and independent stored result (board / view revision) |
|---|---|
| Check 61; press Space on B's toggle. Shift-click 59 with 61 hidden. Open **Expand group** on B. | B kept `2 items`; 61 stayed selected. The range included 59 and 61. Expansion restored the two original rows with 63 unchecked. Folded IDs `[B]` at 8/2, then `[]` at 9/3. Selection made no writes. |
| Choose **Collapse group** on B. From its heading **Select all items in group**. Reload. | Toolbar reached 3 while B remained folded. Reload showed only 59, three headings, no selection. `[B]`, 10/4. Empty C's select-all action is unavailable. |
| As Owner move folded B up by its menu. As Member choose **Collapse all groups** on expanded C; **Expand all groups** on B; toggle C. | B moved with its fold: order B,A,C at 11/4. All folded at 12/5, all open at 13/6, only empty C folded at 14/7. Expanding a populated group restores its own rows, never those of its namesake. |
| Another authorized Viewer opens the board, expands C, folds all, expands B, then reloads. | Only B's rows were shown before reload; after reload both Work sections were open and C folded. No presentation or structural write; still 14/7. |

The reference fixture deliberately set C's physical collapsed flag **true** while the main view's folded-ID list was empty. C opened **expanded** on that view and **collapsed** without the view callbacks. Saving the main view never changed the physical flag. On a fresh fixture, drag folded B by name before A, then drag C before folded B: both drops committed (`B,A,C` then `C,B,A`), with no view save. Reload and expand B: its rows are still 61,63.

**Operation and recovery.** Add the smallest board-scoped main-table presentation read/save needed by the preview. Carry a positive **view revision**, independent of the board revision. A single command updates one or many displayed physical IDs under current board/workspace write access. Lock and validate before updating, preserve unrelated settings, and acknowledge after commit. Reject malformed, duplicate, excessive, missing or foreign targets; never let a label, client role or stale snapshot authorize a write. Pre-packet boards and newly created boards begin expanded at the initial presentation revision without changing existing order, revisions or flat reads. Preserve complete bounded grouped reads (including when all are folded) and native contracts. Do not create a view picker or an API for replacing arbitrary settings.

The reference save handler offers the proposed settings for review on failure. In the preview distinguish a rejected change from a possibly committed one: show the failure, do not present an unconfirmed fold as saved, and provide a fresh authorized read. A stale view baseline requires reload and a deliberate new action. Failed confirmation or refresh retries only the read. A current Viewer can still fold locally; a denied stale write must not turn into silent local success. Ignore late responses from a departed visit. The general settings-draft review UI remains open.
