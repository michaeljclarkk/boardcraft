# 26-browser-board-preview

On one local origin a user can sign in, see the boards available to their account and log out. Serve an original HTML/CSS/JS page at `/preview/` only in an explicitly started preview mode on `127.0.0.1:0`. Reuse the [Rust handler](../crates/mobile-edit-host/src/lib.rs): JSON `POST /session`, bearer `GET /session`, `GET /navigation/boards`, `POST /session/logout`. Use relative same-origin requests, no redirects carrying credentials, third-party assets, CORS relaxation, cookies, proxy server or new authentication mechanism. Keep the bearer in page memory only. Ordinary and navigation hosts keep their current entry points and wire contracts. `/boards/{id}` remains an API, not the preview page.

**Interaction.** Start with a labelled, focused `Username or email` field. Next (including Enter) requires nonempty input and makes no account request. Focus the required masked `Password` field; `Change` restores the entered identifier and clears the password/error. Guard repeated submission while busy. Unknown identifier and incorrect password produce the same correctable alert, without protected content. After successful sign-in, resolve the session before fetching the list. Render returned names as text in a semantic list, in server order, each row bound to its board UUID. No clickable destination, editor or save affordance. `Refresh` requests current visibility. An authorized empty result shows `No boards`; an unavailable list clears stale rows and offers `Retry board list` on the same session. A rejected session returns to sign-in. `Log out` waits for acknowledgment, then clears protected content and returns focus to the empty identifier; failure offers explicit retry. Do not treat a transport fault as an acknowledged logout.

**Runtime gate:** `cargo test --locked -p boardcraft-mobile-edit-host --features browser-smoke --test browser_preview -- --test-threads=1`. Require both enabled cases below. Use one fresh `rustday_test` schema, synthetic Viewer and [packet 23 catalog](../crates/mobile-edit-host/tests/fixture/selection.rs) per case. Launch a real Chromium process with a new temporary profile and a private automation connection. No attaching to an existing session, choosing the default profile, OS input, or clipboard. Drive the rendered controls with pointer and keyboard events. Check accessible names, actual focus, masked type, visible row bounds/order and IDs; no synthetic DOM, injected responses or direct calls to view handlers. Keep generated passwords and tokens out of argv, URLs, logs, traces, captures and assertion messages. Bound browser/DB waits; fail on a missing browser, DB, checkpoint or assertion. Close only the owned browser, host and schema and delete the temporary profile, including on failure.

- `browser_reject_correct_list_logout`: empty Enter stays on identifier; an unknown identifier advances without I/O, then password submission rejects. Change back, use the fixture identifier and a wrong password; require the same alert, focused correction and **zero sessions on a fresh DB read before correction**. Enter the correct password. Observe one successful login, resolution then list request; compare the visible `(UUID, name)` sequence with independent stored catalog positions/names and grants: 203 `Quartz`, 202 `Review`, 201 `Review` (UUID integers); 204 `Hidden` absent. Database checks must not call the list operation as their oracle. Confirm the one verifier is linked to the Viewer. Establish a separate same-account peer via the account operation. Click Log out: require a clean identifier screen, no rows and no automatic sign-in. Reconnect to PostgreSQL: only the peer verifier remains; its client still resolves. Grants and both Review boards' ordered items/revisions are unchanged.
- `browser_empty_unavailable_then_retry`: sign in normally and verify the original list. Remove only workspace membership through the fixture; explicit Refresh now shows `No boards`, no stale rows. Restore membership. Make one list request genuinely unavailable (e.g. hold an exclusive lock on the fixture's catalog table past its scoped lock timeout); Refresh must offer retry with no rows and **no** empty-state message. Release the fault: no automatic login or reload. Click Retry; the same ordered UUIDs return. On fresh connections check the same session verifier/account, unchanged subscriptions and the expected membership at empty, unavailable and recovery; on both Review boards check 62 `Outline`/1 and 73 `Sketch`/1 above 61 `Ink`/1 respectively. Do not lock a shared table or add a test route.

Provide a single command which can populate the real masked form from an in-memory generated password and park the visible browser on the signed-in list without printing secrets or requiring a clipboard handoff. Keep it open until explicitly closed/stopped, then clean up. The unattended gate must finish without opening or waiting for this foreground run. Browser reload/session restoration, password reset, board opening, history, full sidebar and mobile browser layout remain open. Record comparison limits, actual DB and browser observations and the foreground command in `handoffs/26-browser-board-preview.json` only after implementation.
