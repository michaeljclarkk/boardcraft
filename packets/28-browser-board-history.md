# 28-browser-board-history

Make the **Board** address usable in the [loopback preview](../crates/mobile-edit-host/src/preview/page.js). Keep `/preview/` as its list. Each available board has a real same-origin `/boards/{uuid}` link. Plain click or Enter changes the URL and fetches the selected UUID; **Back to boards** navigates to the list. Browser Back and Forward follow actual history entries and fetch the current result for that address. Retry, refresh and completion of sign-in do not push another entry. On direct document entry keep the requested board URL through identifier, rejected password and successful sign-in. Resolve the new session, then load that board, without visiting or selecting from the list.

**Document versus data:** only preview mode may serve the static sign-in shell for a top-level GET navigation to a canonical board address. Distinguish the browser document request (navigation mode and document destination) from an ordinary HTTP/API read; neither header confers access to any data. Use absolute preview asset paths and the existing no-store/CSP headers. Do not install a catch-all or change the scoped JSON GET/PUT contract, `Host::start`, or `Host::start_with_navigation`. All protected reads still use `GET /navigation/boards` or `/navigation/boards/{uuid}` with the page's in-memory session. A URL/history entry identifies a destination; it never contains rows, grants, credentials or a return URL supplied by someone else. Clear previous content on route changes and ignore superseded responses, including a traversal during an outstanding request. A 401 returns to sign-in, a 403/404 keeps the destination with no items and allows retry, a service fault remains distinguishable. No new resolver, storage, writes or schema.

**Source comparison:** in isolated Chromium the source session gate held a direct board URL at sign-in and mounted the requested UUID only after login and session resolution (synthetic auth replies). Its routing hook pushed a list and a different board, then restored the corresponding UUID/list in both traversal directions. Separately, the actor-scoped destination and row operations on a disposable database returned `Sketch`, `Ink` for the last `Review`, only `Outline` for the other, and unavailable for the same board after removal of closed-workspace membership. Restoring membership returned the original rows. The full reference can replace the plain board URL with a resolved saved/Main view. This packet covers **plain board identity**, not canonical view selection; it retains Boardcraft's memory-only browser login. Session restoration, independent tabs, share/clipboard, item/view URLs, malformed-route UI, expired-session history, full grid and native history remain open.

**Gate:** extend the [headless Chromium suite](../crates/mobile-edit-host/tests/browser_preview.rs) on a new temporary profile/private pipe and fresh `rustday_test` schema per journey. Use the [Viewer catalog](../crates/mobile-edit-host/tests/fixture/selection.rs); activate mounted links by pointer/keyboard and traverse Chromium's real history (for example, `Page.getNavigationHistory` + `Page.navigateToHistoryEntry`). Do not synthesize `popstate`, call the router, or use page-injected fetch. At each boundary assert the address, accessible rendered state, exact Fetch methods/paths and selected response status. Independently reconnect to check membership, exact subscriptions, session/account (compare sole verifier privately), and ordered IDs/titles/revisions on **both** duplicate boards. No credentials in paths, history, command lines or traces.

Correct it: exactly POST session, GET session, selected GET 202 (200); only 62 `Outline`, original URL/history entry, no intervening list/201 request and one Viewer session. **Back to boards** must work even without a prior in-app list entry.
- `preview_document_preserves_scoped_api` (host regression in `loopback_board_access`): separate document and ordinary requests on the same board path. In preview mode only the canonical document can get the public shell, with no data. A no-bearer scoped-target JSON read still returns 401, its authorized read returns its own rows, and a valid bearer cannot read a different target through the scoped endpoint. Navigation/scoped-only hosts do not serve this shell. Noncanonical paths and a non-GET must not gain a shell fallback. Keep the existing selected-read, list and Viewer-write denial tests.
