# 30-browser-session-resume

Open a plain board URL in a second independent tab of the same browser session, or reload that tab. Keep its address and history entry. Resolve the existing session before mounting protected controls, then read **that** board under current permissions. No list detour, password prompt, extra login, cached grant or write replay. A missing session starts at the identifier. An unavailable resolve shows only **Retry connection**; keep the session for explicit retry. An authoritative rejection forgets this session and returns to the empty identifier. A board 403/404 is a destination denial, not a session rejection. Acknowledged logout revokes only the presented session; both live tabs leave protected content at their respective addresses without a focus/refresh gesture in the other tab. A failed pre-commit logout leaves both tabs signed in; do not signal success. Invalidate old loads/editors before changing focus so late completions and blur cannot restore content or submit a draft.

**Preview transport.** Keep the account bearer on the Rust host. Use a host-only, HttpOnly session cookie (SameSite=Strict or Lax, no persistent expiry, Secure on HTTPS). A cookie is **not port-scoped**: never put the bearer or any independently usable session handle in it. For example, pair a fresh random cookie handle with a separate random per-login binding held in browser-managed **exact-origin** storage, sent only by relative same-origin fetch in a custom header. Only the matched pair selects the issued session in a bounded per-preview host table; neither half authenticates or can be exchanged alone. Namespace cookies per preview to avoid collisions. Never return the native bearer in the browser login body or persist it, even for tests. No application credential files, Windows Credential Manager, passwords in storage, or credentials in links, history, notifications, traces or diagnostics. A credential-free same-origin change signal prompts the other tab to discard stale UI and check its own current session; the message is not an identity. A transport with equivalent isolation and lifecycle is acceptable with the same tests and a documented rationale.

Scope browser authentication to preview mode. Derive the allowed origin from the bound loopback listener, not forwarded/client headers. Require its exact authority and reject foreign, null or ambiguous origins; for browser mutations including login/logout require a single exact Origin and non-simple same-origin request, no credentialed CORS or redirects. Preserve existing native JSON login and explicit bearer API contracts; no cookie fallback on those paths and no ambiguous credential selection. Reuse the existing account operations and transactional board read/write authorization. Session restoration grants no new board or write capability. Keep no-store and the existing CSP.

**Comparison:** in an isolated Chromium profile the actual reference sign-in gate mounted board 201 after sign-in and board 202 in an independent tab after a fresh resolve. Reload of 202 with an unavailable resume showed retry without the protected child; retry remounted 202. Failed logout kept both mounted; acknowledged logout returned both tabs to sign-in. Sign-in in one also refreshed the other. A later 401 on reload cleared both; the next reload made no auth request. This ran the reference component and logout function with synthetic HTTP statuses and a fixture child, not its database or full grid. Its origin-local token restores an HttpOnly transport cookie. This translation compares the tab behavior without copying a reusable bearer into browser storage. Browser/host restart, saved views, live board edits and deployment remain open.

**Gate:** add two enabled journeys to [browser_preview](../crates/mobile-edit-host/tests/browser_preview.rs). Use the real preview, the existing catalog, one disposable `rustday_test` schema and an owned headless Chromium/private pipe per case. Use distinct top-level targets in the same private context, independent URLs/history and per-tab observations; no opener state, injected fetch/storage/session or synthetic storage events. Assert methods, paths, statuses, resolve-before-read order, visible IDs/controls, absence of protected DOM on failure and no unexpected login/PUT. At each boundary independently reconnect and compare session verifier/account privately, current role/grants and ordered IDs/titles/revisions on **both** boards. Never dump request/response headers, credentials, digest values or CDP messages.
