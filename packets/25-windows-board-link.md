# 25-windows-board-link

From an already opened, read-only board in Windows **browse**, choose **Share**. Offer its **Board** address, a selectable read-only field, **Copy link**, and **Open in new window**. Explain that recipients need existing access. The reference board header offers Board and current-view destinations separately. Board uses the current application origin plus `/boards/{board-uuid}`, even when the address bar contains a resolved view. Copy success follows the clipboard write; on failure leave the address selected for manual copy and do not report success. Copying neither invites anyone nor changes access. Keep the selected UUID with the accepted page; never infer it from a row, board label, position or the host's scoped edit target.

Use the exact connected loopback origin (`http://127.0.0.1:<port>`) and only the canonical board path. Treat it as a **navigation address**, not a request to the scoped `/boards/{id}` item API. The new-window action opens an independent Kit destination without changing the source window. In another connected browse window allow a recipient to paste that address into an **Open board link** control. Both entry points must use the same parser and the production `EditClient::read_selected_board` off-thread, under the opening window's own authenticated context. A new window opened by the sender can reuse that sender's in-memory client. Never open an arbitrary URL or forward a bearer to the origin in pasted text. Reject wrong origins, credentials in the authority, malformed IDs, extra path, query or fragment locally before I/O; use a generic correctable error, without echoing rejected text into logs. Do not encode a password, bearer, session, actor, grant, workspace, title or view in the address. No new HTTP route, OS protocol registration or browser launch.

**Gate:** add two enabled `windows_smoke` cases, serially, using the current project's production Windows Kit controls, packet 23 navigation host and a fresh `rustday_test` schema per case. Exercise mounted controls with pointer/keyboard events, real clipboard copy/paste and distinct window identities; do not construct the pasted URL from fixture IDs or inject navigation results. Use a fixture-only clipboard in a dedicated graphical Windows session, or arrange an attended clipboard handoff before running on a shared desktop. Do not inspect, log or save unrelated clipboard contents. For owner-visible spot checks agree on the foreground turn, leave the reference board open, and stop after each requested observation rather than repeatedly taking focus.
