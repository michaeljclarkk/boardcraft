# 27-browser-board-navigation

Open either `Review` in the signed-in [browser preview](../crates/mobile-edit-host/src/preview/page.js). Render one keyboard-operable control per returned board UUID, in list order. A plain activation sends exactly one relative `GET /navigation/boards/{uuid}` with the page's existing bearer. Use the [selected-board handler](../crates/mobile-edit-host/src/lib.rs): it resolves the session, checks the current workspace and board grants, and reads ordered items in one transaction. The earlier list is neither a grant nor an item cache. Keep the direct `/boards/{id}` API target-scoped. No new endpoint, write action, schema, browser credential storage or reference assets.

Display only the returned item IDs and titles for that selection, read-only and in response order (bind IDs to rows; render titles as text). **Back to boards** fetches the list again. Clear the old items when leaving the selection or requesting another; guard duplicate actions and late responses. A denied/missing destination (403/404) shows **Destination unavailable** with no protected rows. Keep the session and offer explicit **Retry destination** by the same ID or **Back to boards**. Distinguish a service failure (retryable load error) and 401 (clear session and return to identifier). A successful empty list is **No boards**, never a denial. Refreshing a list must not replay a selection.

**Reference comparison:** in the actual sidebar component, the two equal links each selected their own workspace/board IDs and closed the picker. Separately, on a disposable reference database, a subscribed Viewer in a closed workspace resolved the second board and its default view and read `Sketch`/1 above `Ink`/1; the first yielded `Outline`/1 alone. Removing only workspace membership made the same second ID unavailable without a board, workspace or view identity; the refreshed list was empty. After restoring membership, explicit selection returned the original rows. The reference web shell validates the destination before mounting the board, offers retry or workspace navigation on failure, and pages table rows by view/group. This packet compares selection and access outcomes. Its flat read-only list and in-page return do not establish URL/history, saved views, paging, full grid/sidebar or live-revocation parity.
