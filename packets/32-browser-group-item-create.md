# 32-browser-group-item-create

Create one ordinary top-level item at the bottom of a physical group on the selected board. Use the [packet 31 fixture](31-browser-board-groups.md): board 201, last `Work` (`g-20`), which already contains 59 `Ink`. Enter ` Ink `; after commit and again after document reload, that group shows **two** `Ink` rows, 59 then the new UUID. The first `Work`, empty `Reserve`, archived content, other `Review` board and direct host target keep their records and order.

**Reference comparison.** In isolated Chromium the actual group add input generated a random UUID before submit. Whitespace-only Enter made no request; Escape cleared typed text. Enter submitted the raw name, UUID, board/group IDs and creation revision zero, with no parent. The save operation rejected 128 emoji (256 UTF-16 units); the control kept the spelling and offered Retry. Correcting to ` Ink ` submitted the **same UUID**. The operation committed `Ink`/1 under that ID; the input cleared. The grouped read placed it after 59. A new draft used a different UUID. Changing the request actor to Viewer before Enter rejected it, with no partial row; after reload the add input was disabled. This comparison used the reference control and board submit function, a small group renderer/transport adapter, real actor-scoped save and board/group reads on disposable PostgreSQL, and fresh independent raw readbacks. It did not run the full sign-in shell. The reference saves a null source position on ordinary create (manual positions first, then creation time and ID). For the existing explicit-position store, **append within that group**, including zero for its first row, without renumbering neighbors. This matches fixture order, not nullable-position imports.

**Write contract.** Add one matched-browser-session `POST /preview/api/navigation/boards/{board}/items` with bounded JSON `{id, group_id, title}`. The POST means create (revision zero); never accept the actor, an edit hint, position or revision from the page. In one transaction resolve the session, use the current selected-board write policy, check/lock the active group on that board, validate the non-nil ID and shared trimmed title (1–255 UTF-16 units), serialize append allocation and persist the row and its creator. Report the accepted ID, group, title and revision only after commit. An explicit replay of the same accepted creation by its creator in the same scope returns the existing row, without another append, rename or revision. Other actors’ IDs, foreign-board IDs and preexisting rows without creation provenance cannot be adopted. No destructive upsert, globally assigned position, or fake authors on old rows. Preserve the [group migration and native flat reads](../crates/board/src/store.rs); any extra schema version must work after v3 and on a fresh install. Keep native bearer and direct-target routes as they are.

**Control.** Mount `Add item to <group>` / `+ Add item` inside each active physical section, keyed by board/group IDs, disabled for read-only access. Enter or Add submits once; blur does not. Whitespace-only submission does nothing; Escape clears an unsubmitted draft. While pending disable that entry, show saving and do not insert a row or increase a count. Validation rejection retains its exact local text and UUID with a group-local error/Retry; correction submits the same UUID. After acknowledgment clear the submitted draft, rotate its ID and refresh the selected grouped read. Discard superseded completions on navigation or session change. Never automatically repeat a POST, including after an uncertain acknowledgment or failed refresh; offer a fresh authorized read. On 403 recheck the destination with the same session; no writable stale controls or replay. On 401 return to sign-in. The reference’s actor/group-scoped draft storage across reload, subitems, other field defaults, activity/automation effects and native create UI remain open.

**Gate.** Add these enabled top-level cases using the existing preview host and [grouped fixture](../crates/mobile-edit-host/tests/fixture/selection.rs). Assert actual method/path/status/counts and group-local rows/counts. At each rejection, before correction and after commit/reload, reconnect independently: check exact item IDs, groups, positions, titles and revisions including 57, board 202 and the direct target, current grants and the original session/account (privately). For the browser’s generated ID, correlate the synthetic create request, accepted response, rendered row and DB row; never dump unrelated bodies or credentials.
