# 23-windows-board-navigation

Open a board from a connected Windows Kit list without supplying its UUID at launch. Add `boardcraft-desktop browse <loopback-port>` alongside the existing direct-board entries. Reuse the configured exact-origin session or interactive masked sign-in, resolve it and fetch `EditClient::list_boards` off the UI thread. Render one selectable control per returned summary in host order, keyed by board UUID. Do not deduplicate labels, prefetch item rows or open the first board automatically. This is the board-list portion of navigation; it does not translate the workspace picker, folders or browser history.

A plain selection opens **that ID** through a fresh authorized read. Provide a read-only selected-board view with the accepted, ordered item labels and an action to return to a freshly loaded list. Keep connected editing via the existing direct-board entry. On a denied or missing destination show `Destination unavailable`, with no prior or selected board rows, editor or write action, and a way back to the list. Do not fall back to a sibling, show a cached board, sign out a valid caller, or replay an open on refresh. An empty list is a successful `No boards` state with refresh; a service fault offers retry and no protected rows; a rejected session returns to identifier entry. Guard duplicate actions and late completions. Do not persist credentials or navigation grants.

On a navigation-enabled loopback host add an explicit **read-only** selected-board route, e.g. `GET /navigation/boards/{board-uuid}`, and a matching `EditClient` operation. Resolve the bearer and check the current active catalog policy for this board and its workspace in the transaction that loads its rows. Reuse the existing access predicates, grant locks and ordered store read. Do not install a mutable host-wide “selected board”, grant access from an earlier list, expose unclassified pre-catalog grants through this route or enable any new PUT. Ordinary hosts expose neither navigation route. On both host modes `/boards/{id}` GET/PUT must remain restricted to the configured target.

Use a fresh `rustday_test` schema per case. In a closed workspace, a synthetic Member is a workspace member and subscriber to visible private boards `Quartz` (position 0) and two distinct `Review` boards (positions 1, 2). Insert out of display order. Include an unsubscribed private board. Seed the *second* `Review` with `Sketch` and `Ink` in order at revision 1 and the first with a distinguishable sibling row. Configure the scoped item target as a different board. Keep the session in memory on the exact origin. Compare exact IDs, order and values, not just counts or headings:

- `loopback_board_access::selected_board_read_checks_current_membership`: use actual requests to open the non-target second `Review` and verify its rows. The ordinary host must not serve the selection route and the navigation-enabled host must still reject non-target GET/PUT on its scoped routes. Check the hidden and unclassified boards cannot be opened by UUID. Remove only workspace membership on a separate connection; the same caller's selected read must now be denied with no row payload, although session and subscription still exist. Revoke the bearer separately and require session rejection, not an empty board. Verify the selected and sibling rows and revisions remain unchanged independently.
- `windows_smoke::opens_selected_board_by_id`: in a graphical Windows process without DB or actor configuration, inspect mounted Kit controls, their IDs, labels and screen order: `Quartz`, `Review`, `Review`, no hidden board or item controls. Click the last `Review`; require only its two expected ID-bound labels, in order. Return to the list and open the first `Review`; show only the sibling's row. No login replay or save. Check the session account link and both boards' stored IDs, titles and revisions on fresh connections at the checkpoints.
- `windows_smoke::revoked_membership_blocks_board_selection`: after the controls are mounted but **before** clicking the last `Review`, remove membership independently and leave the board subscription intact. Click the stale control; observe unavailable with neither board's item labels, editor nor save action. Return to the list with the same session: `No boards`, no stale selectors. Restore membership independently and explicitly refresh; the same controls reappear in order without auto-opening. Click the second `Review` and verify its own rows. Check the session, membership, subscription and unchanged rows at denial and recovery. Use actual pointer events and the production handler, not direct view calls or injected results.

Reference comparison: in a synthetic DOM the workspace sidebar showed `Quartz`, `Review`, `Review`; clicking the last link passed the workspace and second `Review` UUID and closed the picker. Separately, the destination and board operations opened `Sketch`/1 above `Ink`/1. After membership removal that same UUID resolved as unavailable with no board, workspace or view identity; refreshing the fixture list returned no boards. Restoring membership and explicitly selecting reopened the original rows. These observations do not establish end-to-end browser timing or automatic sidebar refresh.
