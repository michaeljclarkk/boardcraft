# 21-windows-connected-logout

Offer `Log out` on a connected Windows board, including a read-only board. The reference account menu waits for the logout POST before clearing the local session and reopening at identifier entry. A request failure is reported in the current view; it does not sign the user out. The server deletes only the presented session's verifier, independently of board write access. Use the existing Kit button, `EditClient::logout` and host `revoke` operation. Keep network I/O off the frame thread, guard duplicate clicks while pending, and prevent old save/load completions from restoring a signed-out board. Preserve the existing Enter/blur contract; perform the logout checks from display mode.

On a failed request show `Could not log out` with the board and `Log out` still available. Retry only on user action. Do not infer from a lost acknowledgment that the server still accepts the token; each future protected operation remains authorized by the host. On acknowledgment drop the client, rows, editor and notices, and show an empty `Username or email` input and `Next` in the same window. **Read the origin/token configuration only at launch.** Do not reload it, mutate the process or parent environment, persist a password or bearer, or use developer recovery/SQL. A new launch with an unchanged, revoked configured token goes through normal session rejection.

Gate: add both enabled cases to `windows_smoke`. Use real graphical child processes without database or actor configuration, the production loopback host, and a fresh `rustday_test` schema per case. Drive and inspect mounted Kit controls, not view methods or injected responses. At each checkpoint independently read both rows (ordered UUIDs 42 then 17, titles and revisions) and the exact session verifier/account links on fresh connections; compare verifiers privately, never print them. Keep fixture credentials in memory, with the configured pair only in the child's launch environment and interactive passwords delivered on stdin to the masked-input driver. No secrets in arguments, logs, captures or files.

- `configured_logout_failure_then_retry`: start with two `Review`/1 rows, an exact-origin configured Member session A and an independent same-account peer B. Both can read. Interrupt **only the child's** transport before its logout reaches the host; click `Log out`, observe the retryable failure, both labels still mounted and both original sessions intact. Check that only B's verifier remains, B resolves and reads those rows, and A is rejected on resolve/read/rename. Reopen a fresh window with the same unchanged launch pair: it must reject A and show sign-in without disturbing B or either row.
